# ТЗ-FT-DEEP-001 — 42-місячний oracle-прогін FT-ядра (NYBUY + London BUY)
**Дата:** 2026-07-25
**Статус:** ЗАМОРОЖЕНЕ ТЗ (pre-registered). Правки після контакту з даними ЗАБОРОНЕНІ.
**Мотивація:** весь профіт AK47_FT робить NYBUY: +$14,830, PF 9.71 — але на **17 угодах** за 7 місяців, з яких 88% результату припадає на січень–лютий 2026 (один трендовий режим). Липень 2026: 22 дні, 2100 HTF-блоків, **нуль входів**. Це статистично нерозрізненно з везінням (для розділення edge +0.5R від шуму при SD≈1.4R потрібно ~90 угод). Стара версія AK47_AI також показувала PF 1.56–1.74 у тестері й померла на 42-місячному oracle (EV −0.044R, −106R). **FT через цю глибину перевірки не проходив.**

## 1. Мета
Відповісти на єдине питання: **чи має FT-ядро (NYBUY + London BUY) реальний edge, чи це режимна ставка на трендові періоди?**

## 2. Двигун — витяг з AK47_FT_EA_156.mq5 (parity-контракт)
Реплікувати `ProcessNYBuy()` / `ProcessLonBuy()` ТОЧНО. Ключові елементи:

**Стейт-машина (M5, по закритих барах):** IDLE → RAIDED → RECLAIM → ENTRY.
1. **Сесійне вікно:** NYBUY `utcH ∈ [InpNYAlertStartUTC, InpNYAlertEndUTC)`; LonBUY — відповідне London-вікно. Середа блокується при `InpBlockWednesday`.
2. **FT-імпульс:** `HasFTImpulse(1, atr)` — при `InpUseFTFilter=false` (default) завжди true, тобто в базовому прогоні НЕ фільтрує. Зафіксувати як no-op.
3. **HTF-гейт:** `HTFAllowBuy()` — D1/H4 bias. Це головний блокувальник (у липні 2026 дав 2100 блоків і нуль входів) — реплікувати точно, логувати кожен блок.
4. **Рівень:** `FindBestSellSideLevel()` — sell-side ліквідність; дедуп: один рівень = один спрацьовуючий сигнал на день.
5. **Raid:** low[1] пробиває рівень. **Same-bar reclaim** обов'язково (55 з 94 oracle-сигналів мають reclaimLag == raidLag) — перевірка на ТОМУ Ж барі, потім на наступних до `FAST3_BARS`.
6. **Reclaim:** close[1] > level.price. Далі очікування пробою high реклейм-свічки, timeout 12 барів.
7. **Вхід:** `entryPx = reclaimHigh + _Point` (stop-логіка на пробій, але після sweep+reclaim — НЕ чистий breakout).
8. **SL:** `raidPrice − atr14 × InpSLBufferATR`, clamp по STOPLEVEL. **TP:** `entry + slDist × InpTakeProfitR`.
9. **Фільтри відхилення (в порядку коду):** BAD_ENTRY_BLOCK (entryLag), SL_TOO_TIGHT_USD (`InpMinSLDistanceUSD`), FAR_FROM_SWING_HIGH (`nybDistSwATR > InpMaxDistToSwingHighATR`, H1-ATR — НЕ M5), LATE_RAID_BLOCK (raidLag), SWEEP_TOO_SHALLOW (`sweepATR < InpNYBuyMinSweepATR`), SLATR_OUT_OF_RANGE.
10. **Quality-гейт (емпіричний, НЕ плоский поріг):** h1bias проти напрямку → reject завжди; qScore ≥ 100 → accept; qScore ≥ 93 AND reclaimCP ∈ [0.80, 0.90) → accept. Інакше reject.
11. **qScore** — `CalcQualityScore()` з v1.56 включно з session-бонусами (module 0 = NY-вікно UTC, module 1 = London-вікно UTC).

**Усі параметри — defaults з v1.56. Тюнінг ЗАБОРОНЕНИЙ на всіх етапах.**

## 3. Дані
- XAUUSD **M5** (+ M15/H1/D1 агрегація для bias/ATR), той самий брокер-фід, що використовувався для BH-валідації (провенанс і sha256 зафіксувати у звіті).
- Вікно: **2023-01-01 .. 2026-07-23** (~42 місяці). Warmup: мінімум 200 D1-барів до першої оцінюваної угоди.
- Якщо повні 42 місяці M5 недоступні — виконати на максимально доступному вікні і ЗАФІКСУВАТИ фактичну глибину у звіті (гейти нижче перераховувати НЕ можна; при вікні < 24 міс результат = INCONCLUSIVE).

## 4. Конвенції виконання
- Вхід: stop-ордер на `reclaimHigh + point`; fill за фактом пробою наступними барами (M5-бар: якщо high ≥ entryPx → fill по entryPx).
- Виходи: SL/TP по high/low наступних барів; при дотику обох в одному барі — **SL пріоритет** (консервативно).
- Кости: **−0.05R/угоду** (та сама конвенція, що у BH_OOS_002 v2).
- Портфельні гейти EA (daily stop, MaxConcurrent, circuit breaker) — **виключені** (oracle-конвенція, для порівнянності).
- Модулі рахувати РАЗОМ (FT-ядро) і ОКРЕМО (NYBUY / LonBUY).

## 6. Вердикт-правила (pre-registered; пост-хок правки заборонені)
- **GO (edge доведений):** EV_net ≥ +0.10R І N ≥ 90 І **обидві OOS-половини плюсові** → FT-ядро доведене на тій самій глибині, що спростувала AK47_AI. Дозволяє розмову про ризик/масштаб.
- **REGIME (режимна ставка):** EV_net ≥ +0.10R, АЛЕ хоча б одна OOS-половина ≤ 0, АБО топ-3 місяці дають > 70% сумарного R → едж існує лише в трендових режимах. Наслідок: FT НЕ торгує постійно; наступний крок — режимний класифікатор (ONNX-роадмап), а не масштабування.
- **NO-GO:** EV_net < 0 → FT-ядро йде слідом за AK47_AI у каталог falsified; демо зупиняється.
- **INCONCLUSIVE:** N < 90 на повному доступному вікні АБО глибина даних < 24 міс → вердикт відкладено, зафіксувати фактичні N/EV як проміжні.
