## 1. Мета

Перевірити, чи піднімає **навчений шар відбору** очікування на пулі
сигналів, зібраному з багатьох незалежних торгових механік.

Це перенесення структури, яка виміряно працює у FXArena, на XAU.

### Виміряний прецедент (FXArena, EURUSD)

```
весь universe 291 659 епізодів, геометрія TP2/TO120:
   EV net = −0.2069R    WR 36.3%    Total −60 347R

відібрані 3 535 (monthly top-4%, LogisticRegression, WF):
   EV net = +0.5230R    WR 63.5%    Total +1 848.87R

підйом від відбору: +0.7299R на угоду, частка 1.21%
```

Сама геометрія FXArena **збиткова**. Увесь прибуток створює шар відбору.

### Гіпотеза

> На XAU пул сигналів від 15–20 різних механік містить підмножину,
> яку можна відібрати каузальними фічами, і EV відібраних перевищує
> EV випадкового входу того ж періоду і напрямку.

### Чого лабораторія НЕ перевіряє

- Прибутковість окремих ботів. Боти тут — **генератори кандидатів**,
  не стратегії. Їхня індивідуальна EV не є критерієм.
- Режимну маршрутизацію як окрему гіпотезу. Режим входить **фічею**
  в модель, а не групувальником. Це відрізняє лабораторію від закритої
  `SPEC_XAU_REGIME_MATRIX_v002`, де брак DOWN-місяців зробив клітинки
  непорівнюваними.

## 3. Пул генераторів

**15–20 механік, витягнутих з коду OsEngine** (`project/OsEngine/Robots/`).

Критерій включення: **різна механіка, не параметричний клон**.
Обґрунтування: `Trend/`, `VolatilityStageRotationSamples/`, `FuturesTrend/`
і більшість `Screeners/` — варіації пробою каналу. Включення п'яти
варіантів одного індикатора створить **штучну згоду** і зробить фічі
співпадіння беззмістовними.

### Склад (фіксується до прогону, поіменно)

```
Трендові:      пробій каналу, канал лінійної регресії, Keltner,
               Parabolic SAR, Alligator, MACD, Momentum
Контртрендові: Bollinger, RSI, Williams %R, PriceChannel-контртренд
Патернові:     пін-бар, три солдати, розворотна свічка
Волатильнісні: ATR-розширення, Stochastic
```

Кожна механіка реалізується **однією канонічною версією з фіксованими
параметрами**. Підбір параметрів заборонений.

Таймфрейми: **M5, M15, H1**.

## 4. Модель угоди

Однакова для всіх кандидатів — інакше вони непорівнювані.

```
вхід       закриття бару сигналу; BUY по ask_close, SELL по close(bid)
SL         1.5 × ATR(14) того ТФ
TP         3.0 × ATR(14)     (RR = 2.0)
тайм-аут   120 барів того ТФ
вихід      по M1: BUY по bid, SELL по ask
R          від фактичних сторін котирування; mid ЗАБОРОНЕНО
```

Обґрунтування заборони mid: медіана спреду зросла 9 → 48 пунктів
(2023 → 2026). Розрахунок від mid зробив би ранні періоди штучно
прибутковими і модель вивчила б календар.

Неоднозначні угоди (SL і TP в одному M1-барі) позначаються `AMBIGUOUS`.
Якщо частка > 3% — обов'язковий тіковий арбітраж.

## 5. Фічі

Усі каузальні: рахуються на закритті бару **до** входу.

### 5.1 Власний сигнал
```
bot_id                      яка механіка
bot_class                   trend / countertrend / pattern / volatility
direction                   +1 / −1
timeframe                   M5 / M15 / H1
signal_strength             нормована сила умови спрацювання
```

### 5.2 Співпадіння — ключовий блок
```
n_bots_active               скільки механік спрацювало в цьому вікні
n_same_direction            скільки в той самий бік
n_opposite_direction        скільки проти
agreement_ratio             n_same / n_active
n_trend_class               скільки трендових
n_countertrend_class        скільки контртрендових
class_conflict              чи є одночасно trend і countertrend
n_timeframes                на скількох ТФ збіглося
```

Виміряна життєздатність (5 архетипів, H1): 36.6% активних барів мають
≥2 механіки; з них **69.9% — конфлікт за напрямком**. Блок наповнений.

### 5.3 Режим — фіча, не групувальник
```
atr_ratio        ATR(14) / ATR(100)
kaufman_er       ER(20)
slope_sma1200    SMA(1200) − SMA(1200)[t−240]      напрямок
vr               ATR(480) / ATR(4800)              волатильність
```

Персистентність виміряна: нахил SMA1200 — 93.1% через 120 барів
проти 57.1% випадкових, медіана серії 1 365 барів. `atr_ratio(14/100)`
з квантилем 0.60 **не персистентний** (+0.5 пп) і як групувальник
непридатний — але як фіча допускається.

```
hour             серверна година
```

### 5.5 Вартість

## 6. Шар відбору

```
модель          LogisticRegression(C=0.5) + StandardScaler
мітка           net_R > 0
валідація       monthly walk-forward
межа навчання   exit_t епізоду < перший вхід тест-місяця
відбір          щомісяця топ 4.0% за p_win
```

Частка **4.0%** зафіксована наперед за прецедентом FXArena.
Її зміна після перегляду результату заборонена.

---

## 7. Базова лінія — НЕ нуль

Критично. Золото зросло 1745 → 4622 (+165%). Виміряно: випадковий лонг
дає **+0.200R на OOS-1 і +0.172R на OOS-2** без жодного еджу.

```
base(місяць, напрямок) = EV випадкового входу тієї самої моделі угоди,
                         у тому самому місяці, того самого напрямку,
                         ≥1500 семплів на комбінацію

excess = EV_відібраних − base
```

Усі пороги застосовуються до **excess**, не до сирого R.

## 8. Пре-реєстровані пороги

```
GATE-1  підйом від відбору
        EV_excess(відібрані) − EV_excess(увесь пул) ≥ +0.30R
        обґрунтування: FXArena дає +0.7299R; половина цього —
        консервативна планка для перенесення на інший інструмент

GATE-2  абсолютний рівень
        EV_excess(відібрані) ≥ +0.10R
        збігається з канонічним порогом користувача

GATE-3  стабільність
        знак EV_excess однаковий на OOS-1 та OOS-2
        мінусових місяців ≤ 20% від загальної кількості

GATE-4  permutation — ОБОВ'ЯЗКОВИЙ
        200 шафлів мітки всередині місяця, повний пайплайн
        реальний EV_excess > p95 нуля

GATE-5  N ≥ 300 відібраних угод на кожному з OOS-1 та OOS-2
```

**Усі п'ять мають пройти.** GATE-4 не може бути пропущений або
позначений N/A.

## 9. Стеля

Перед основним прогоном вимірюється стеля пулу: EV при **ідеальному**
відборі (знати результат наперед, брати всі позитивні).

Прецедент з попередньої роботи: на XAU H1 при цій моделі угоди
ідеальний вибір сторони і бару дає **+1.992R**, торгуючи 65% барів.

Якщо стеля пулу нижча за GATE-2 — лабораторія закривається одразу,
без навчання моделі.

## 11. Що читається з результату

Якщо gates пройдено — з ваг моделі читається **матриця
«механіка × режим × напрямок»**: які боти в яких умовах модель бере,
а які відкидає.

Ця матриця є **наслідком**, а не задається руками. Її не можна
використовувати для відбору механік і повторного прогону — це був би
post-hoc відбір.

## 13. Що вважається успіхом

Успіх — однозначна відповідь при дотриманні протоколу.

**«Шар відбору не піднімає EV» — повноцінний результат.** Він закриває

## 14. Відомі обмеження

- Реалізації механік — мої переклади з C# OsEngine, не оригінальні
  роботи. Розбіжність можлива.
- Одна модель угоди для всіх. Контртрендові механіки з TP на 3 ATR
  структурно в невигідному становищі. Це свідомий розмін на
  порівнюваність; окрема геометрія на механіку — предмет іншої
  лабораторії.
- DOWN-режим у IS+OOS представлений слабко (найсильніші падіння
  в CONTROL). Модель побачить мало ведмежих умов.
- Прецедент FXArena отриманий на EURUSD із фічами взаємодії з рівнем
  (`micro_touch_number`, `level_age_hours`, `attack_path_atr`).
  Тут фічі іншої природи. Перенесення структури не гарантує
  перенесення результату.
